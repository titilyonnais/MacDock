# Publication sur GitHub — plan 52

> **Pour les agents :** exécution en ligne, tâche par tâche, tests d'abord. Reprendre à la première tâche non cochée.

**But :** MacDock s'installe sur tous les PC de l'utilisateur depuis un dépôt GitHub public, `titilyonnais/MacDock`. Chaque
version est un installateur `.exe`, construit et publié par GitHub Actions. La mise à jour automatique fait l'objet du
plan 53 ; ce plan pose la version, l'installateur et les publications sur lesquels elle s'appuie.

## Choix de l'utilisateur (9 octobre, au réveil)
- Dépôt **public** `titilyonnais/MacDock`, licence **MIT** (titulaire : `titilyonnais`).
- **Installateur .exe** (Inno Setup), construit par GitHub Actions à chaque version.
- Son prénom et son dossier utilisateur retirés **de tout l'historique** avant le premier envoi : historique réécrit,
  sauvegarde complète gardée (`git bundle`).

## Choix
- **Version** : `MAJEUR.MINEUR.CORRECTIF`, le mineur étant le dernier plan fusionné (0.52.0 pour ce plan). Une seule
  source, `src/core/version_defs.h` (macros), lue par le C++ (`kMacDockVersion`, À propos) et par les ressources
  `VERSIONINFO` des quatre exécutables (Propriétés > Détails de Windows). La publication vérifie que l'étiquette `vX.Y.Z`
  correspond à cette version.
- **Installateur** (`installer/MacDock.iss`) :
  - **installation** : par utilisateur, sans droits d'administrateur, dans `%LOCALAPPDATA%\Programs\MacDock` ;
  - **contenu** : les quatre exécutables, le dossier `windhawk` (l'app Réglages y trouve les mods), `LICENSE` et `README.md` ;
  - **menu Démarrer** : MacDock (le lanceur) et Réglages MacDock ;
  - **démarrage avec Windows** : coché par défaut, même valeur `Run\MacDock` que `MacDockLauncher.exe --install` ;
  - **avant de copier** : MacDock est quitté proprement, en 30 s au plus :
    - ordre d'arrêt au lanceur (événement `Local\MacDockQuit`, aussi `MacDockLauncher.exe --quit`) : il ferme le Dock
      puis la barre et ne relance plus rien ;
    - fenêtres du Dock, de la barre et de l'app Réglages fermées à chaque seconde (lanceurs plus anciens) ;
  - **après** : relancé ; si l'installation échoue, l'ancien est relancé une fois tout à fait arrêté ;
  - **paramètres** :
    - `/NOLAUNCH` et `/NOSTARTUP` (essais) : ni lancement ni démarrage automatique ;
    - `/RELAUNCH` (mise à jour au démarrage) : relancé même s'il ne tournait pas ;
  - **variante d'essai** (`make-installer.ps1 -Test`) : identifiant, nom et dossier à elle, une vraie installation
    n'est jamais touchée ;
  - **désinstallation** : refusée si MacDock ne s'arrête pas ; démarrage retiré s'il visait cette copie ; thème de
    Windows rétabli s'il avait été changé (`MACDOCK_KEEP_THEME=1` pour les essais) ; réglages de `%APPDATA%\MacDock` gardés,
    comme sur macOS.
- **Runtime C++ intégré** (`/MT` en Release) : un Windows neuf n'a pas forcément le redistribuable Visual C++, que
  l'installateur ne peut pas poser sans droits d'administrateur. `make-installer.ps1` refuse un exécutable qui en
  dépend (`dumpbin`), ou qui contient le chemin du dossier de l'utilisateur (`/PDBALTPATH`).
- **GitHub Actions** (action épinglée par empreinte de commit, jeton non gardé après le checkout) :
  - `ci.yml` (chaque envoi, toutes branches) : build Debug et Release, tests ; deux tests qui demandent une sortie
    audio et la Calculatrice sont sautés sur la machine de GitHub (`SKIP_ON_CI_IF`) ;
  - `release.yml` (étiquette `v*`) :
    - l'étiquette doit viser un commit de `main` et correspondre exactement à la version ;
    - Inno Setup 6.7.3 téléchargé chez son auteur et vérifié ;
    - installateur `MacDock-Setup-X.Y.Z.exe` et `SHA256SUMS.txt` joints à la release ;
    - relançable après un échec partiel.
- `build.ps1` : SDK 10.0.26100.0 s'il est installé, sinon celui par défaut de Visual Studio (machines de GitHub).

## Revue : points d'attention
- Une mise à jour installée par-dessus MacDock en marche : rien de verrouillé, MacDock relancé ensuite.
- Installation ratée ou annulée : MacDock revient quand même.
- Aucune donnée personnelle dans le dépôt public (historique compris), aucun secret dans les workflows.
- Le démarrage avec Windows suit l'emplacement installé, pas l'ancien `build\Release`.

## Essais réels
Sur ce PC, avec la variante d'essai de l'installateur (dossier `MacDock-essai`), ton MacDock arrêté pendant les essais
puis relancé :
- installation pendant que MacDock tournait : arrêté par ses fenêtres, fichiers 0.52.0, entrée de désinstallation ;
- `MacDockLauncher.exe --quit` : tout arrêté, rien relancé ;
- mise à jour pendant que la copie tournait : ordre d'arrêt reçu, copie, relance en 2 s ;
- mise à jour ratée (fichier verrouillé) : retour arrière, ancienne version relancée, qu'elle tournait ou non
  (`/RELAUNCH`) ;
- désinstallation : tout retiré, réglages gardés ;
- démarrage avec Windows : posé à la première installation, respecté aux mises à jour, retiré à la désinstallation.

Plus `dumpbin` : aucun des quatre exécutables ne dépend du runtime Visual C++. CI verte sur la machine de GitHub
(Visual Studio 2026, Windows Server 2025).

## Relecture
Un défaut critique, corrigé : les exécutables dépendaient du runtime Visual C++, absent d'un Windows neuf. MacDock
installé n'y aurait pas démarré, et ce PC, qui a Visual Studio, ne pouvait pas le montrer. Ils sont maintenant compilés
avec le runtime intégré, et la fabrication de l'installateur le contrôle.

Corrigés aussi :
- **arrêt** : ordre d'arrêt au lanceur, fenêtres refermées à chaque seconde pendant 30 s, relance seulement une fois
  l'ancien arrêté, `/RELAUNCH` ;
- **essais** : variante de l'installateur à part ; mon nom d'utilisateur n'est plus inscrit dans les exécutables ;
- **installateur** :
  - message d'erreur juste ;
  - démarrage retiré seulement s'il vise exactement cette copie ;
  - désinstallation refusée si MacDock ne s'arrête pas ;
  - deux installateurs jamais en même temps ;
  - fichiers Windhawk listés un par un ;
  - thème de Windows rétabli à la désinstallation ;
- **workflows** : action épinglée, jeton non gardé, délais, étiquette sur `main` et à la casse exacte, publication
  relançable ;
- **versions** : zéros en tête refusés, numéros de préversion de toute taille comparés.

Reporté au plan 53, à trancher avec toi : `SHA256SUMS.txt` prouve qu'un installateur est intact, pas qu'il vient de
toi. Un compte GitHub volé suffirait à publier une fausse version, que la mise à jour automatique installerait en
silence. Il faudrait une signature avec une clé gardée hors de GitHub.

Mineurs reportés :
- **Windows 11 N** (sans Media Feature Pack) : `MacDock.exe` lie Media Foundation au démarrage et ne s'y lancerait pas ;
- **démarrage avec Windows** : une valeur de démarrage qui vise une version compilée à la main reste si la case est
  décochée à la première installation ;
- **Bac à sable Windows** : pas d'essai dedans (fonction non activée sur ce PC) ; `dumpbin` en tient lieu.
